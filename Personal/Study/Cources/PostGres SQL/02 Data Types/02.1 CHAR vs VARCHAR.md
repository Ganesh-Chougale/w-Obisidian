The primary difference between CHAR(n) and VARCHAR(n) in PostgreSQL is how they handle trailing spaces and string storage length. 
## 1. Key Differences

* Space Padding: CHAR(n) always pads the string with spaces to match the exact length n. VARCHAR(n) stores the string exactly as it is, without adding extra spaces. 
* Storage Size: CHAR(n) always uses the same amount of space regardless of the text length. VARCHAR(n) only uses space proportional to the actual characters entered.
* Performance: In PostgreSQL, there is no performance difference between the two types.

## 2. Side-by-Side Comparison
If you create a column with a limit of 5 characters (n = 5) and insert the word "cat":

| Feature  | CHAR(5) | VARCHAR(5) |
|---|---|---|
| Value Stored | "cat " (padded with 2 spaces) | "cat" (no spaces added) |
| Character Length | 5 characters | 3 characters |
| Best Used For | Fixed-length data (e.g., country codes, MD5 hashes) | Variable-length data (e.g., names, email addresses) |

## 3. PostgreSQL-Specific Behavior
Unlike some other databases (like MySQL or SQL Server), PostgreSQL does not offer a speed advantage for using CHAR(n). In fact, PostgreSQL documentation recommends using VARCHAR or plain TEXT for almost all situations because CHAR(n) adds overhead to strip trailing spaces during comparisons.
